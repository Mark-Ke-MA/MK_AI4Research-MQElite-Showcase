# 核心机制与取舍

**中文** | [English](../docs_en/MECHANISMS.md)

## 1. 先判断日期，再下载正文

[DurablePollingSource](../src/mqelite/codex/source.py) 先用 `itemsView="notLoaded"` 调用 `thread/turns/list`，保留 turn 身份、生命周期状态和时间戳；再沿服务端返回的不透明游标读取开始或完成时间可能落入所需区间的 turn 正文。元数据清单在读取器内部缓存。

正文批次超出传输大小上限时，重置连接并将批量减半；单个 turn 仍超限则报错。读取正文时若相关元数据变化，会丢弃缓存并完整刷新一次所需窗口；再次变化则向调用方报告。含活动 turn 的缓存再次使用前会失效。

取舍是用额外元数据及定位请求换取较少的正文下载，并不保证读取成本恒定：元数据仍覆盖历史，相关正文可能很大，源变化也可能触发刷新。公开测试使用内存中的协议夹具，不能证明所有 Codex 版本均兼容。

## 2. 文件已提交、账本失败之后如何恢复

[DailyReconciler](../src/mqelite/storage/reconcile.py) 计算规范字节及其摘要，持有人格每日锁，通过暂存、验证和原子替换提交变化的 JSON，然后更新摄取账本。

第二步失败时，重试发现权威文件已经匹配，保留该文件并修复状态。所选回归测试会注入这个故障；相同输入的第二次正常执行不会重写文档。这不是跨文件系统和 SQLite 的单一事务，而是让部分成功具有明确恢复顺序。

[atomic.py](../src/mqelite/storage/atomic.py) 展示暂存与 fsync 顺序，[layout.py](../src/mqelite/storage/layout.py) 展示显式路径、权限模式和受管理路径的符号链接检查。

## 3. 可验证地保留归档证据

[build_archive](../src/mqelite/archive/bundle.py) 将每日原始字节写入 tar/gzip 包，配合确定性的成员元数据与 manifest。外部 manifest 绑定压缩包字节，成员哈希绑定未压缩的每日文件。验证检查身份、日期、路径、大小、哈希和格式约束。旧格式读取器允许未知字段，同时保留原始字节。

可重复性以输入完全相同为前提，包括调用方提供的创建时间和工具版本。哈希证明相对可信 manifest 的完整性，不等于数字签名认证。

[archive_ready](../src/mqelite/archive/eligibility.py) 在日历截止条件之外加入完整性、冲突、索引和运行状态条件。构建出包不意味着可以删除热文件。保留的 `commit_archive` 原语负责写入代际和活动指针；更上层的计划、索引协调、覆盖验证及热文件清理没有复制进本仓库。

## 4. 保持召回便宜、有界、可解释

[分词](../src/mqelite/index/tokenize.py) 采用 Unicode NFKC 与大小写折叠，提取 Latin 词及重叠的 CJK 二元、三元字符片段；单字符片段保留一个字符。SQLite FTS5 先取有上限的候选集，[检索逻辑](../src/mqelite/index/database.py) 再按词项重合计分，加上规范化子串匹配奖励，并可选应用最高 1.1 倍的近期权重。

结果受条数和内容字符数约束，可按角色与日期过滤。字符预算不是模型 token 预算；遇到首个超预算结果会停止，所以即使后方存在更短结果，也可能返回空列表。候选上限和词法匹配同样意味着它不是穷尽式语义检索。

召回只读打开已就绪索引，不在提问时创建缺失索引或修复未就绪索引。所选测试比较查询前后的数据库字节及修改时间，并验证缺失或未就绪状态不会触发修复写入。

## 优化的判断依据

日期优先读取通过减少无关正文传输降低读取成本。判断这种优化是否成立，需要同时比较规范输出是否保持一致和读取范围是否缩小，而不只观察请求是否变快。这里的[合成测试](VALIDATION.md)验证正文筛选、缓存与异常处理行为，不提供真实在线性能 benchmark。
